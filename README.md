추가 주차열이 들어가는 직선 내부 통로는 2xTwo에서 1xTwo로 좁힙니다. 건물 전면도로·다른 도로와의 충돌·중앙도로 이격·제외 범위를 확인하고, 주차칸 앞 차량 통로를 유지합니다. 주차장 묶음 내부의 남는 면적은 포장하며, 의도적으로 설정한 녹지 섬은 유지합니다. 전체 재계산에서는 주차장 구성도 바뀌므로 총 주차면 증가를 보장하지는 않습니다.

AP 투명 통로가 중앙도로와 실제 노드를 공유하면 중앙도로 중심까지 사다리꼴 포장을 연장합니다. 포장은 내부 이음매를 둥글게 잘라 생기던 작은 구멍을 피하도록 합칩니다. 좁고 국소적으로 막힌 녹지 자투리에는 내장 Grass Surface를 배치하며 큰 공원·지정 녹지에는 적용하지 않습니다.

단지 상세 패널은 제목과 번호를 한 줄에 표시하고 내용 높이에 맞춥니다. 선택한 건설 완료 단지에서 주차 차량/주차 용량, 입주 세대/주거 용량과 비율을 약3초 간격으로 갱신합니다. 집계는 단지가 소유한 건물과 독립 주차 데칼만 대상으로 하며 가로변 주차는 제외합니다. 주차 용량을 읽을 수 없는 차로는 계획 용량을 표시합니다. 비율은 작은 회색 글씨입니다.

배치 변경은 새 계획·다시 계산에 적용됩니다. 이미 지어진 단지의 도로·표면을 자동 변경하지 않습니다. 빌드/알고리즘 검사를 거쳤으며 실제 게임에서의 표면 표시·실시간 집계는 확인 전입니다.
## 건물 배치 방식과 추가 입구

배치 조건에서 **기본 혼합 / 가로형만 / 세로형만 / 가로·세로형**을 선택할 수 있습니다. 기본 혼합은 기존 알고리즘입니다. 나머지는 ㄷ자·ㅁ자 묶음을 제외하고 지정한 방향의 일자형 건물을 배치하며, 건물 간격·전면도로·주차 조건은 유지합니다. 가로·세로는 카메라가 아닌 단지 정렬축 기준이며, 건물 출입구가 모두 강을 향한다는 의미는 아닙니다. 설정은 재실행 후에도 유지됩니다.

**추가 입구 T자 접속 허용**은 기본 켜짐입니다. 입구가3개 이상이면 먼저 관통도로를 만들고, 추가 입구는 공간이 맞을 때 직선 중앙도로에 T자로 접속합니다. 도로 폭이나 제외 범위 때문에 들어가지 않으면 기존 방식으로 연결합니다. 두 입구의 연결 방식은 유지됩니다. 기존 계획에는 다시 계산 후 반영되며, 이미 지어진 시설을 자동 변경하지 않습니다.

## 오류 보고서 복사

계획·건설 오류는 빨간색 계열로 표시됩니다. 오류 옆 복사 아이콘을 누르면 현재 상태, 건물·도로 선택, 상세 검사 결과와 최근 AP 관련 로그를 클립보드에 복사합니다. 복사 성공 시 체크 아이콘으로 바뀝니다. 자동 전송은 하지 않으며, 최근 로그 일부를 포함한 보고서입니다. 전체 게임 로그는 포함하지 않습니다.

전면도로 연결 오류는 AP의 미리보기 전 검사에서 발생합니다. 건물 앞 내부도로가 입구와 연결된 도로망에 속하지 않거나 건물 전면을 충분히 지나지 못했다는 뜻입니다. 전기·수도 검사 결과를 뜻하지 않습니다. 복사 보고서에서 실패한 건물과 연결/길이 부족을 구분할 수 있습니다.

## 투명도로 표시와 실제 미리보기 처리

AP 도로는 일반 화면에서 표시용 윤곽을 숨기고 게임의 마커 표시 상태를 따릅니다. 화면 표시용 마커만 적용하며 도로 연결·충돌·전기·상하수도·차량 경로 설정은 유지합니다. 기존 AP 도로도 도시 로드 후 표시용 마커를 복원합니다.

실제 미리보기의 생성·검사를 여러 프레임으로 나눕니다. 건물은 한 동씩, 수목·포장·주차 데칼은 작은 묶음으로 나타나며 모든 검사가 끝나야 확정할 수 있습니다. 건물별 도시 전체 도로 탐색 대신 가까운 도로 후보를 사용합니다. 준비 중에는 입력이 잠기며, 준비 완료 또는 오류 표시 후 계획도로 돌아갈 수 있습니다. 도로 연결 그래프의 네이티브 처리와 실제 확정은 게임이 담당하므로 모든 상황에서 프레임 멈춤이 없음을 보장하지는 않습니다. 이 변경의 실제 게임 체감은 아직 확인 전입니다.

## AP 투명도로 이름·썸네일·교체·철거

AP 투명도로9종에 한국어·영어 이름과 설명을 추가했습니다. 내장 소형 도로 메뉴에서 각 유형을 선택할 수 있습니다. 원본 투명도로의 로컬 AssetIconLibrary SVG가 있으면 그 그림을 그대로 사용하고, 없으면 게임의 원본 썸네일 아틀라스를 사용합니다. 우상단 AP 표시는 Segoe UI Bold 윤곽선 SVG로 만들어 글꼴 설치 여부와 관계없이 표시합니다. 원본 아이콘·다른 모드 파일은 수정하지 않으며 생성된 아이콘은 ModsData/ApartmentPlan/RoadIcons에 캐시합니다.

원본에서 상속되던 편집기용 MarkerNet을 AP 도로에서 제외해 일반 도로 교체 도구와 불도저가 선택할 수 있도록 했습니다. 세이브 로드 후 기존 AP 도로의 Marker 및 마커 전용 충돌 제외 상태도 제거합니다. 전기·상하수도·차로·주거 연결 설정과 프리팹 ID는 유지합니다. 도로 폭 확대 등 게임 자체의 건설·충돌 검사는 그대로 적용됩니다. 이번 변경의 실제 게임 교체·불도저 동작은 아직 확인하지 않았습니다.

## 45도 연결 허용

주차장 접속 통로가 같은 방향으로 진행하면서 두 번 직각으로 꺾이면, 양 끝점과 진입 직선부를 유지한 45도 대각선으로 줄입니다. 실제 도로 폭 전체가 건물·주차칸·제외 범위·테두리 여백을 침범하지 않을 때만 적용합니다. 2xTwoway 우선, 공간 부족 시 1xTwoway 규칙은 유지합니다.

엇갈린 반대편 입구의 중앙도로는 공간이 맞으면 45도 대각선과 접선이 이어지는 Bezier를 우선 사용합니다. 곡선 반경·길이 설정은 유지하며, 사용자가 명시적으로 선택한 중앙도로 **직각** 모드는 그대로입니다. 건물과 주차열의 정렬은 회전시키지 않습니다. 기존 미건설 계획은 다시 계산해야 적용되며 이미 건설한 도로는 바꾸지 않습니다.

`docs/diagonal-comparison.png`는 실제 C# 출력 비교입니다. 동일 240×360m·입구 엇갈림80m 시험에서 20동은 유지되고 주차498→455면으로 바뀌었습니다. 접속 통로 독립 시험(4m/7m)은60→50.6m로 줄었습니다. 원래 접속이 직선인 실제 입력 재현은5동192면으로 유지됩니다. 도로 형상에 따라 배치와 주차 수량이 달라질 수 있으며, 이번 변경의 실게임 통행은 아직 확인하지 않았습니다.

사용자는 이번 변경 전에 전입 차량이 실제로 진입해 주차하는 모션을 확인했다고 보고했습니다. 아래 이전 조사 기록과 별개로 사용자 실게임 확인으로 기록합니다.

## 첫 메뉴 열기 부하 개선

건물·도로·주차 데칼 목록은 도시 로드 후 여러 프레임에 나눠 준비하고 재사용합니다. 준비 중에는 패널에 상태를 표시하며 제목줄의 닫기 버튼을 사용할 수 있습니다. 전체 건물의 출입구를 미리 조사하지 않고 실제 사용하는 에셋만 조회·캐시합니다. 에셋 번역 목록도 분할 준비하며 재열기 때 반복하지 않습니다. 실제 프레임 개선 정도는 게임 실행 로그로 확인해야 합니다.

## 도로를 모아서 설계하기

**도로 추가**에서 직선·곡선 SVG 버튼을 선택합니다. 곡선은 시작점 → 조절점 → 끝점 순서입니다. 구간을 완성하면 끝점에서 이어 그릴 수 있습니다. 점을 찍는 동안에는 녹색 미리보기만 표시하고, **도로 설계 확정** 또는 Enter로 전체 구간을 한 번 계산합니다. 우클릭은 최근 점/구간 취소, 옆 닫기 아이콘은 미확정 도로 전체 취소입니다. 계산에 실패하면 원래 계획도와 미확정 입력을 복원합니다. 입력을 확정·취소한 뒤 저장/건설할 수 있습니다. 패널을 닫아도 미확정 입력은 현재 세션에 유지되지만 도시 저장에는 포함되지 않습니다.

주차 차량이 갑자기 나타나는 현상은 아직 해결로 확정하지 않았습니다. 게임 자체에도 신규 차량 생성·주차 위치 보정 과정이 있습니다. 단지 연결 검사에 주차칸의 시작/끝 차로, 차량 상태와 미연결 교차로 정보를 추가했습니다. 차량 AI나 원본 에셋은 바꾸지 않았습니다. 실제 운행 후 돌아오는 차량의 주차 과정은 추가 게임 확인이 필요합니다.

## 전입 데이터·진입 통로·전체 삭제 수정

AP 투명도로에서 빠졌던 게임의 주택 탐색용 서비스 커버리지 데이터를 추가했습니다. 기존 AP 도로도 세이브 로드 후 누락된 데이터를 보완합니다. 건물 에셋의 접근 유형·주거 속성은 변경하지 않습니다. 실제 전입에는 시뮬레이션 진행과 정상적인 도시 경로·수요가 필요하며 실게임 확인은 아직입니다.

주차장 진입부는 배치 초기부터 2xTwoway의 실제7m 폭을 먼저 확보하고, 공간이 부족하면1xTwoway로 계산합니다. 기존 미건설 계획은 다시 계산해야 합니다. 이미 지어진 도로의 폭은 자동 변경하지 않습니다. 최신 구역 출력은5동192면이며, 넓은 통로 확보로 기존204면보다12면 줄었습니다. `docs/wide-access-latest.png`는 실제 알고리즘 출력입니다.

**단지 전체 삭제**는 보호 검사를 통과하면 게임 내장 확인 팝업을 자동으로 띄웁니다. 확인해야 실제 철거하며 취소하면 유지됩니다. 다른 소유물이나 게임 오류 때문에 검사가 실패하면 삭제하지 않습니다. 건설 후 창을 닫아도 해당 단지의 연결·입주 진단을 로그에 남깁니다.
## Bezier 도로·부지 포장·단지 상세 창

중앙도로와 수동 곡선은 실제 Bezier 도로 구간으로 건설하며 분기점에서만 나눕니다. 주차장 진입 통로는 AP 2xTwoway의 실제 폭이 들어갈 때 우선 사용하고, 불가능하면 좁은 내부도로를 유지합니다. 저장된 계획은 다시 계산해야 적용되며 이미 건설한 도로를 자동 교체하지 않습니다.

배치 조건의 **건물 부지 타일 포장**은 기본 ON입니다. 켜면 AP가 새로 배치하는 건물의 기존 표면만 제거하고 내장 Tiles Surface 01로 부지를 채웁니다. 원본 에셋은 수정하지 않으며 기능성 구역은 유지합니다. OFF는 기존 에셋 표면을 보존합니다. **노출된 surface 모서리 반경**은 기본2m, 슬라이더·숫자로0~4m 설정합니다. 도로·다른 구역과 맞닿지 않은 모서리만 네 조각으로 둥글게 처리합니다.

단지 정보는 좌상단의 독립 겹침창으로 표시합니다. 단지 경계를 클릭하거나 저장 목록에서 선택하면 열립니다. 건설된 단지의 **연결 상태 검사**에서 차량 교차로 양방향 연결, 수도·전기 및 입주 상태를 다시 검사할 수 있습니다. AP 투명도로는 일반 도로용 차량 경로 설정과 교차로 상태를 사용하며, 불필요한 보도로의 차량 접속을 차단합니다. 이 코드 검사와 빌드는 실제 차량 통행·전입 확인을 대신하지 않습니다. 실제 게임에서 연결 검사와 시뮬레이션 진행을 확인해야 합니다.

계산 결과 이미지: `docs/native-geometry-comparison.png` (7동159면, 기존79구간→Bezier68구간). SDK·알고리즘·모의 UI 검사와 인게임 동작 검증은 구분합니다.
## 밀착 주차줄과 넓은 통로

등을 맞댄 주차줄에는 건물 간격을 맞추기 위한 추가 녹지 틈을 넣지 않습니다. 사용자가 주차 녹지섬을 켠 경우 지정 폭은 유지합니다. 남는 폭은 연결된 통로에 배분하며, AP 투명도로를 선택했고 2xTwoway Road Path 프리팹이 사용 가능하면 실제 폭을 반영해 넓은 구간에 사용합니다. 해당 프리팹이 없거나 Alley를 선택하면 선택한 내부도로 폭을 기준으로 배치합니다. 넓은 도로의 주차칸도 해당 도로에 네이티브 부착됩니다. 기존 계획도는 다시 계산해야 새 배치 규칙이 적용됩니다.

## 유휴 녹지 조경

패널 제목줄의 나무 아이콘을 누르면 **녹지 조경** 보조 패널이 열립니다. 별도로 드래그·스크롤할 수 있고 ESC는 보조 패널부터 닫습니다. 나무 종류와 초기 나이(묘목·어린 나무·성목·노목)를 복수 선택하고 밀도를 슬라이더 또는 숫자로 지정합니다. 기본은 NA/EU 목록에서 무작위3종, 어린 나무+성목,1,000㎡당 목표12그루입니다. 다시 추첨 버튼으로3종을 새로 고를 수 있습니다. 설정은 게임 재실행과 계획도 편집에 유지됩니다. 실제 수량은 수관 크기와 녹지 폭에 따라 줄며 단지당 최대1,500그루입니다.

일반 계획도에서도 나무 위치와 수관을 원으로 표시합니다. 조경 패널의 예정 수량과 실제 건설 미리보기는 같은 배치 결과를 사용합니다. 실제 미리보기 중에도 밀도·수종·나이를 변경할 수 있으며 입력을 마치면 미리보기를 재생성하고 검사를 다시 합니다. 검사가 끝난 뒤 다시 명시적으로 확정해야 건설됩니다. 초기 나이 이후에는 게임의 정상 성장 규칙을 따릅니다. 건물·도로·주차칸·포장·외부 시설 제외 범위에는 배치하지 않으며, 생성 나무는 단지 소유 목록에 포함되어 전체 철거 시 함께 삭제됩니다. 나이 선택은 한 줄의 묘목·어린 나무·성목·노목 SVG 아이콘으로 표시하며 hover로 이름을 확인합니다. 이미 건설된 단지에 자동으로 덧심거나 기존 나무를 교체하지 않습니다.

**건설 후 Grass Sprites 적용**은 호환되는 Grass Sprites 모드가 활성화되어 있으면 기본 ON, 없거나 꺼져 있으면 OFF/비활성입니다. 사용자가 OFF로 정하면 그 선택을 유지합니다. 실제 건설 확정과 잔디 마스크 로딩 완료를 기다린 뒤 유휴 녹지만 작은 묶음으로 칠합니다. 사용자가 Grass Sprites 브러시를 쓰는 동안에는 잠시 멈춥니다. 기존 잔디를 지우거나 Grass Sprites의 전역 설정을 바꾸지 않습니다. 잔디 저장은 Grass Sprites의 도시별 저장 기능을 사용하며 공유 마스크이므로 단지 철거 시 자동 삭제하지 않습니다. 모드를 끄거나 단지 철거를 시작하면 미완료 잔디 작업이 중단됩니다. 경계와 매우 좁은 녹지는 브러시 픽셀 폭을 확보할 수 없으면 제외됩니다.

SDK/알고리즘/브라우저 모의 UI 검사와 실게임 동작은 별개입니다. 실제 수목 렌더링·성장·단지 철거 및 Grass Sprites 저장/로드는 게임 검증이 필요합니다.
## 주차장 통로 폐쇄

가까운 평행 주차 통로의 열린 끝은 내부도로 폭의 공간이 있으면 서로 연결합니다. 연결은 실제 도로 중심선을 잇고, 건물·주차칸·외부 시설 제외 범위·테두리 여백을 침범하지 않는 경우에만 만듭니다. 도로로 닫힌 주차장 안쪽의 빈 땅은 pavement로 채웁니다. 저장 계획도는 편집 후 다시 계산해야 새 배치 규칙이 반영되며 이미 건설한 시설은 자동 변경하지 않습니다.
## 계획도 삭제와 최소 이격

저장 버튼 오른쪽의 빨간 휴지통 아이콘으로 작성 중인 초안이나 편집 중인 저장 계획도를 삭제합니다. 게임 내장 확인 팝업을 거치며 계산·건설 미리보기·철거 처리 중에는 사용할 수 없습니다. 실제 건설물을 가진 단지는 일반 계획도 삭제 대신 단지 상세 패널의 전체 철거를 사용합니다.

배치 조건의 **메인 도로 최소 이격**과 **테두리 최소 이격**은 슬라이더·숫자 입력으로 각각0~20m를 설정합니다. 기본값은 둘 다4m입니다. 메인도로 이격은 도로 중심선이 아닌 가장자리부터 건물·주차칸까지 적용하며, 연결도로는 통과할 수 있습니다. 테두리 여백도 입구·필요한 보행 연결은 통과할 수 있습니다. 기존 저장 설정값은 보존되므로 이전에 저장된 메인 도로 이격6m는 자동으로4m로 덮어쓰지 않습니다. 변경값은 재실행 후에도 유지되고 다시 계산한 계획도에 반영됩니다.

## ESC 닫기와 에셋 번역

패널이 열려 있으면 ESC로 먼저 Apartment Plan 패널을 닫습니다. 검색창·숫자 입력 및 계산 중에도 적용되며, 닫힌 뒤에는 게임의 일반 메뉴 입력으로 돌아갑니다. 계획도 데이터는 닫기로 삭제하지 않습니다.

에셋 카드·툴팁·선택 목록은 게임의 현재 언어 번역을 사용합니다. 번역이 없으면 게임의 영어 사전을 사용하고, 영어도 없으면 원본 에셋 이름을 표시합니다. 검색은 표시된 번역 이름과 원본 에셋 ID 모두 지원합니다.

## 단지 관리·Road Path·기존 지형

내부 도로는 차량·보행 통행이 가능한 **AP Invisible Road Path 1x/2x 양방향** 또는 Alley를 사용합니다. Car Path는 제외합니다. 중앙 도로 목록은 게임 번역 이름으로 표시하며 **2차로 도로**를 앞에 표시합니다. 주차선 겹침은 기존처럼0~0.3m까지 조절됩니다.

건설 확정 후 채운 계획도는 숨겨지고, 단지에 마우스를 올리면 경계가 표시됩니다. 클릭하면 기존 단지 상세 패널에서 편집·삭제할 수 있습니다. 계획도 편집만으로 이미 건설된 도시 오브젝트를 자동 이동·교체하지는 않습니다.

**평탄화 기능은 제거했습니다.** 이전 설정에 ON이 저장되어 있어도 적용하지 않습니다. 미리보기와 확정 모두 현재 지형을 사용하고 지형 변경·대기·재검사 단계가 없습니다. 기존 지형에서 발생하는 게임의 건설 오류는 그대로 검사합니다.

외부 시설 제외 범위는 바깥 구역을 완성한 뒤 새 다각형으로 여러 개 그릴 수 있습니다. 시작점 클릭이나 구역 완료로 닫습니다. 해당 범위는 단지 배치에서 제외됩니다. 인접한 지상 도로의 실제 보행 가능 여부와 위치를 확인한 곳에는 유휴 공간을 통해 중앙도로와 연결되는 보도를 만듭니다. 건물·주차칸·제외 범위를 피하고 최대 3회 꺾이는 짧은 경로만 채택합니다. 인접 도로가 없거나 장애물·높이 차이가 크면 연결하지 않습니다. 가까운 주차줄 사이에 폭·연결 조건이 맞으면 내부 통로를 만듭니다.

계산 중에는 어두운 반투명 로딩 화면과 SVG 별 애니메이션을 표시합니다. 예상 인구는 현재 도시의 거주 세대 표본 평균 인원 × 단지 세대수입니다(최대4096세대,60초 갱신). 표본이 없으면 숫자를 임의로 만들지 않습니다.

배치 변경 비교: `docs/management-layout-comparison.png`. Road Path4m 시험에서 판상형23동496면·도안자이9동296면의 연결·기하 검사를 통과했습니다. 파일/모의 UI 검사와 실게임 검증은 별개입니다.

## AP 도로 검사와 주차 데칼 조회 수정

AP 투명 도로는 일반 도로에 없는 기본 차로 목록 대신 게임의 실제 도로 구성 계산 경로로 전기·상수도·하수도 차로를 검사합니다. 준비가 확인된 AP 도로는 내부 도로 목록에 표시되며 Alley 대체 선택도 유지합니다.

CSKRParkingDecalClosed1x는 해시 없는 ID로 조회하지 않고, 게임에 로드된 실제 프리팹 엔티티를 찾아 크기 계산과 건설에 함께 사용합니다. 로컬·구독본이 함께 로드되면 구독본을 우선합니다. 에셋 파일을 수정하거나 다시 가져오지 않습니다. 수정 후 실제 목록 표시·건설·전기·수도 동작은 게임에서 확인해야 합니다.

## 내부 도로 Alley 대체와 스냅 버튼

AP 투명 도로가 초기화 검사를 통과하지 못하면 내장 **Alley(골목길)**를 내부 도로로 선택합니다. 중앙 도로 선택은 유지합니다. 목록에는 Alley와 사용 준비가 확인된 AP 양방향 도로가 표시되며, 실제 선택한 폭으로 다시 배치합니다. 확인된 Alley 폭은8m입니다. 찾을 수 없는 도로를0m로 표시하지 않습니다. 기존 계획도의 도로가 대체되면 원래 미리보기는 유지하고 다시 계산 후 저장·건설하도록 안내합니다. 이미 건설된 도로는 자동 교체하지 않습니다.

맞춤 버튼은 **전체 / 도로 경계 / 부지 경계 / 직각 / 건물 경계 / 연장선 / 구역 격자** 순서입니다. 전체 버튼은 여섯 맞춤 모드를 함께 켜거나 끕니다. 다각형 닫기 토글은 제거했으며 시작점 클릭과 구역 완료는 유지합니다.

동일 시험 부지48,000m²·중앙도로16m에서 내부 Alley8m를 사용한 계산 결과는 도안자이9동151면, 판상형18동356면입니다. 도로 연결과 기하 검사는 통과했으며 실게임 차량·보행·수도·전기 작동은 미검증입니다. `docs/internal-road-alley-comparison.png`는 실제 계산 결과의 비교 이미지입니다.

## 계산 중 멈춤과 0동 표시 수정

배치 계산은 게임 업데이트 스레드에서 기다리지 않고 독립 작업으로 실행합니다. 계산 중에는 기존 미리보기를 유지하고 저장·건설을 잠시 막습니다. 새 요청은 이전 결과를 무효화하며 최신 입력의 결과만 반영합니다. 도시 전환·새 계획도에서도 이전 계산 결과를 버립니다.

AP 도로를 못 찾았을 때 내부 배치 폭과 연결 검사 폭이 달라져 모든 건물 후보가 탈락하던 경로를 수정했습니다. 필수 네트워크가 초기화되지 않았다면 면적 부족으로 안내하지 않고 도로 미준비 상태를 표시합니다. 초기 프리팹 검사가 실패한 도로도 나중에 다시 검사하며, 통과 조건은 완화하지 않습니다.

`Logs/ApartmentPlan/layout-network-state.json`에 선택한 도로·초기화 상태를, 계산 실행 시 `layout-last-input.json`과 `layout-last-result.json`에 재현 입력·단계별 시간을 남깁니다. 독립 시험 부지33,800m²에서 폭 불일치 조건의0동을 재현했고 수정 후 입구 위치별3·5·7동이 배치됐습니다. `docs/single-entry-width-fix.png`는 그 중 한 사례입니다. 사용자의 화면과 정확히 같은 다각형이 아니며 실제 게임 프레임·건설 동작은 미검증입니다.

## 주변 주차줄 정렬과 통로 연결

추가 주차장은 주변 주차줄의 길이·시작점·끝선을 우선 맞추고, 들어가지 않을 때 짧은 배치를 시도합니다. 통로는 양쪽 끝에서 기존 도로까지 연결을 찾습니다. 교차 통로가 이미 제공하는 주차줄 끝 여유를 이중으로 빼지 않아 남는 폭도 주차칸으로 활용합니다.

동일 시험 부지의 도안자이9동은261→296면입니다. 왼쪽 위는 각 줄10→11면, 중앙은 기존·추가 네 줄 모두13면과 양끝 연결, 하단은 세 줄 모두12면으로 맞췄습니다. 판상형 예시는23동496면입니다. 실제 출력 전후 비교는 `docs/parking-alignment-before-after.png`이며 기존 계획도는 다시 계산해야 합니다. 기하 검사와 실게임 검증은 별개입니다.

## 주차장 빈 공간 보완

열린 주차 구역도 주차줄 끝의 여유·피치 잔여 공간을 pavement로 채웁니다. 건물 배치 후 기존 주차장 근처의 빈 공간에 연결 가능한 내부 통로와 마주 보는 주차줄을 추가합니다. 일반 포장 여유가 들어가지 않는 곳은 선택한 AP 도로의 실제 폭까지 줄여 검사합니다(기본4m 양방향). 중앙 도로에 직접 주차하지 않으며 건물·수동 제외 구역·외곽 녹지와 실제 출입 지점을 보존합니다.

앞선 빈 공간 보완 단계에서는 같은 시험 부지에서 도안자이9동이160→261면, 판상형23동이313→424면이었습니다. `docs/parking-infill-before-after.png`는 당시 비교입니다. 실제 차량 주차·회전 동작은 게임 미검증입니다.

## 주차선 간격과 주차장 포장

주차칸 중심 간격은 **데칼의 실제 폭 − 주차선 겹침 폭**입니다. 기본 겹침0.15m를 적용하면 CS KR1x(폭3m)의 배치 간격은2.85m입니다. 배치 조건에서 겹침 폭을 조절할 수 있으며 기존 계획도는 다시 계산해야 합니다.

도로로 둘러싸인 주차 구역 안쪽의 남는 지면은 pavement로 채웁니다. 수동 제외 구역과 건물 부지는 보존합니다. 실제 건설 미리보기에는 내장 `Pavement Surface 01`을 주차칸·AP 통로·포장 구역 아래 생성하며, 단지 전체 삭제에 포장면도 포함합니다. 면 생성·삭제와 저장 후 재로드의 실게임 검증은 아직입니다.

현재 알고리즘 이미지: `docs/cs-kr-comparison-paved-narrow.png` (시험 부지 판상형23동/496면, 도안자이9동/296면).

## 주차칸 녹지 여백

배치 조건의 **주차칸 녹지 여백**은 기본적으로 꺼져 있습니다(적용 폭0m). 켜면 여백 폭을 슬라이더 또는 숫자로0~6m 조절할 수 있습니다. 설정과 폭은 재실행 후에도 유지됩니다. 데칼 사이 간격, 건물 최소 이격과 외곽 녹지는 별도 설정입니다. 기존 계획도에는 다시 계산 후 반영됩니다.

## 좁은 AP 내부 도로

기본 내부 도로는 `AP Invisible Road Path - 1xTwoway`(내장 원본 폭4m)입니다. 건물 전면과 주차장 통로에 함께 사용하며, 중앙 도로는 기존 선택을 유지합니다. AP 단지 도로 목록에서 1x/2x 양방향 유형을 선택할 수 있습니다. 실제 도로 폭에 기존 포장 여유 설정(기본 양옆1m)을 더해 배치 공간을 확보합니다. 기존 저장 계획도는 AP 도로 선택 후 다시 계산하세요. 이미 건설된 도로는 자동 교체하지 않습니다.

## CS KR 주차칸

기본 주차칸은 사용자의 `CSKRParkingDecalClosed1x`를 사용합니다. 약 3×5.97m 크기와 주차 데칼 간격 설정을 반영하며, 실행 중 읽은 에셋의 실제 크기를 우선합니다. 해당 에셋을 활성화해야 건설할 수 있습니다. 이전 계획도는 다시 계산해야 새 크기와 간격이 적용되며, 이미 지어진 데칼은 자동 교체하지 않습니다.

현재 계산 예시와 최초 참고 이미지 비교: `docs/cs-kr-comparison.png`. 판상형18동/207면, 도안자이9동/80면은 동일한 48,000m² 가정 부지의 결과이며 실게임 검증은 아닙니다.

## 건물 전면 AP 도로 연결

모든 새 배치는 **건물 전면 → AP Invisible Road → 주차장** 순서를 기준으로 합니다. 건물의 실제 프리팹 전면 방향을 따라 AP 도로가 연속으로 지나가고, 각 전면 도로는 단지 내부 연결 도로를 통해 중앙 도로·입구와 연결됩니다. 전면 도로가 주차 통로 역할도 맡으며, 계획도에서는 연한 회색으로 표시합니다. 별도 보도 띠를 강제하는 기능이 아닙니다.

전면 도로는 필수입니다. **배치 조건 → AP 단지 도로**는 초기화 검사를 통과한 AP 양방향 2차로 invisible 도로 중에서 선택합니다. 이전에 일반 도로나 다른 통로를 선택했다면 기본 AP 도로로 전환됩니다. 메인 도로 선택은 유지됩니다. 기존 계획은 **다시 계산**해야 하며, 건설 전에 모든 건물의 전면을 지나는 도로와 입구까지의 연결을 검사합니다. AP 프리팹이 준비되지 않거나 연결이 부족하면 건설을 막고 안내합니다.

기하 검사에서 전면 연결·주차 접근·겹침을 확인했습니다. 실제 차량·주민 이용과 전기·수도 공급은 아직 실게임에서 검증하지 않았습니다. 공급원과 중앙 도로의 실제 설비 연결도 필요합니다.

## 도로 추가

`지하주차장 진입로` 대신 **도로 추가**를 제공합니다. 직선은 시작점과 끝점, 곡선은 시작점·조절점·끝점을 클릭합니다. 끝점에서 연속으로 이어 그릴 수 있습니다. Enter 또는 **그리기 완료**로 종료하고, 우클릭은 입력점 취소 → 입력점이 없을 때 최근 추가 도로 취소 순서로 작동합니다.

도로 모드에서 선택 도로 이름을 누르면 메인 도로 선택 목록이 열립니다. 추가 도로도 같은 선택 네트워크와 실제 폭을 사용하며, 네트워크를 바꾸면 함께 갱신됩니다. 도로 스냅은 기존 도시 도로 및 계획 내 메인 도로의 중심선을 대상으로 합니다. 추가하면 건물과 주차장을 재계산하므로 개별 동 교체는 도로 작업 후 진행하세요. 도로는 단지 경계·녹지 여백·지정 구역 안의 배치 조건을 지켜야 합니다.

추가 도로의 조절점은 계획과 함께 저장됩니다. 실제 시공은 기존 **실제 건설 미리보기 → 확정** 절차로 수행합니다. 이미 시공한 계획에는 재시공 방지를 위해 도로 추가가 비활성화됩니다. 기존 저장본의 진입로 구역은 보존하되 새 생성 기능과 설정은 숨겼습니다. 이번 도구는 지상 직선·곡선 계획 도구이며, 기본 게임 도구의 고가·터널·업그레이드 전체 기능을 대체하지 않습니다. 곡선은 현재 건설 그래프에서 여러 직선 구간으로 근사됩니다. 기하·저장 검사 및 모의 UI 검사와 실제 게임 검증은 구분합니다.

## Apartment Plan 전용 invisible road

게임에 등록된 내장 invisible 네트워크 중 자동차 차선이 있는 종류를 찾아 **AP Invisible ...** 이름의 독립된 RoadPrefab으로 등록합니다. 원본 폭·차선·일방/양방향·주차 차선 구성은 유지하고, 건물 연결 기능 및 내장 Alley의 전기·상수도·하수 구성으로 만든 보이지 않는 설비 구간을 추가합니다. 원본 프리팹과 다른 모드는 수정하지 않습니다. 보행 전용 invisible path는 자동차 도로 복제 대상에서 제외됩니다.

**배치 조건 → AP 단지 도로**에서 단지 생성에 사용할 AP 양방향 2차로 도로를 선택할 수 있습니다. 복제본 초기화 시 원본과의 폭 일치, 건물 연결 버퍼, 설비 용량 및 기본 설비 차선 세 종류를 확인하고, 실패한 항목은 선택 목록에서 제외합니다. `invisibleRoad.registered`, `invisibleRoad.initialized`, `catalog.invisibleRoad`, `construction.network.selected`, `construction.frontage.network` 로그에서 결과를 확인할 수 있습니다.

이 검사는 프리팹 구성 검사입니다. 실제 도시의 입구 연결·주민 출입·주차·전기와 수도 공급·하수 배출·저장 후 재로드는 아직 검증하지 않았습니다. 특히 일방통행 변형의 단지 내부 동선은 별도 실게임 확인이 필요합니다. Pavement surface 자동 생성은 아직 포함하지 않습니다. 새 프리팹 이름은 저장 참조에 사용되므로 임의 변경하지 않습니다.

## 필요한 출입 연결만 생성

건물마다 가상의 전면 출입점을 만드는 동작뿐 아니라, 주차 배치에서 보도 폭만큼 건물 앞을 일괄적으로 비워 두던 규칙도 제거했습니다. 보도 폭을 바꿔도 전면 전체에 띠가 생기지 않습니다. 실제 에셋 출입점에 연결이 필요한 경우에는 해당 지점의 주차열만 나누어 짧은 통로를 확보하며, 건물 간격 때문에 남는 공간은 녹지로 표시합니다. 보행 가능한 도로가 이미 출입점을 덮으면 별도 보도를 생략합니다. 기존 계획은 **다시 계산**해야 반영됩니다. 이미 건설한 보도는 자동 철거하지 않습니다. 기하·출입·주차 검사는 통과했으며 실제 게임 결과는 미검증입니다.

## 편집 중 계획도 삭제

저장 계획을 편집할 때 저장 버튼 아래의 **계획도 삭제**를 누르면 게임 내장 확인 팝업이 열립니다. **예**를 선택하면 해당 계획과 편집 중인 도형을 지우고, **아니요**로 취소하면 유지합니다. 상세 패널의 삭제도 같은 팝업을 사용합니다. 실제 건설 미리보기에서는 비활성화되며, 생성 시설 기록이 있는 단지는 상세 패널의 **단지 전체 삭제**로 먼저 철거합니다.

**건물 전면도로 확보**를 해제해도 도로 없는 건물의 출입·차량 서비스·수도·전기가 자동으로 연결되지는 않습니다. 독립 연결 기능은 현재 구현되어 있지 않습니다. 편집 삭제는 모의 UI 검사를 통과했으며 실제 게임 검증은 미완료입니다. 아래는 이전 변경 기록입니다.

## 슬라이더와 단지 전체 삭제

숫자 입력 항목은 슬라이더와 직접 입력을 함께 제공합니다. 슬라이더를 놓거나 입력값을 확정하면 적용합니다. 실제 건설 미리보기 때 계획도 기록을 자동 보관하며, 배치한 단지를 클릭하면 **단지 전체 삭제 → 삭제 미리보기 → 단지 삭제 확정**으로 철거할 수 있습니다. 이 버전부터 기록된 생성 시설만 대상으로 삼습니다. 이전 버전에서 건설한 시설은 소유권 기록이 없어 자동 일괄 삭제하지 않습니다. 도시를 저장해야 생성 시설 기록도 유지됩니다.

## 선택 표시와 도로 보행 연결 수정

- 스냅 토글은 정적인 선택 테두리만 표시합니다. 다른 활성 버튼은 버튼 자체의 테두리·안쪽 그림자로 애니메이션을 표시하여 별도 테두리의 위치 어긋남을 방지합니다.
- 배치 조건 체크박스 두 개는 한 줄, 메인 도로 모서리 설명과 입구 길이 숫자·단위도 각각 한 줄로 표시합니다.
- 실제 보행 차로가 있는 선택 도로는 보행 연결 대상으로 인정합니다. 해당 도로에 이미 닿은 접근점에는 별도 보도를 강제하지 않으며, 떨어진 후면 접근점에는 필요한 연결을 계획합니다. 차량 전용 도로는 이 조건에 포함되지 않습니다. 기존 계획은 다시 계산해야 적용됩니다.
- 이번 산출물은 **패키지만 제작하며 설치하지 않습니다.** SDK·기하·모의 UI 검사와 실제 게임 검증을 구분합니다. 게임에서의 수정 결과는 미검증입니다.

## 짧은 곡선과 실제 배치

- 복수 입구의 **곡선 구간 길이** 기본값은 기존 대비 50%입니다. 코너의 원호와 S자 전환 구간을 줄이며 입구까지의 연결은 유지합니다. 배치 규칙에서 25~100%로 변경할 수 있고, 기존 계획은 **다시 계산**해야 새 비율이 적용됩니다. 부지·도로 폭 조건에 따라 자동 모드는 직각으로 연결할 수 있습니다.
- 새 계획은 **실제 건설 미리보기 → 실제 배치 확정**, 저장 계획은 좌상단 상세 패널의 **실제 배치 → 미리보기 검사 → 실제 배치 확정** 순서입니다. 선택한 내장 도로·보도·건물과 통로에 부착한 주차 데칼을 게임의 생성·검사·Apply 경로로 배치합니다.
- 이전 저장 형식은 입구·에셋을 지정하여 배치를 재계산해야 합니다. 이전 계획을 무조건 이미 건설된 것으로 취급하던 오류를 수정했습니다.
- 저장된 계획을 실제 배치하면 별도 도시 메타데이터에 완료 상태를 기록합니다. 계획을 다시 저장하지 않더라도 **도시 저장**에는 포함되며 동일 계획의 재배치 버튼을 비활성화합니다. 메타데이터 기록 전의 과거 건설 여부를 자동 추론하지는 않습니다.
- 이번 변경은 SDK, 기하, 직렬화 및 모의 UI 검사 범위입니다. 실제 게임에서 새 곡선·배치·재로드는 미검증이며 Computer Use는 사용하지 않았습니다.

- 배치 규칙에서 코너 목표 반경 8~200m와 주차 데칼 사이 최소 간격 0.1~3m를 조절합니다. 새 기본값은 40m / 0.5m이며 기존 사용자 설정은 유지합니다. 실제 코너 반경은 부지와 접근 길이에 제한됩니다.
- 주차 간격은 내장 데칼의 실제 폭을 기준으로 하며 도로 이격과 별개입니다. 변경은 새 계획이나 다시 계산한 계획에 적용됩니다.
- 기본 선택 도구로 지도 위 저장된 계획을 클릭하면 좌상단 상세 패널이 열립니다. 편집 후 저장하면 같은 계획을 갱신합니다. 도시도 저장해야 재실행 후 유지됩니다.
- 새 저장에는 입구·제외 범위·배치·선택 에셋·설정을 함께 보관합니다. 이전 저장은 남아 있는 경계를 복원하고 입구를 다시 지정해야 하며 주차 면수 등 누락 정보는 표시할 수 없습니다.
- 계획 편집·삭제는 이미 건설된 도시 시설을 이동하거나 철거하지 않습니다.

이번 업데이트의 실제 게임 조작·저장/재로드는 미검증입니다. SDK/기하/직렬화 검사와 모의 UI 검사를 통과했습니다. Computer Use는 사용자가 요청할 때만 사용합니다.

# Apartment Plan 0.1.11 (로컬 시험 빌드)

아파트 단지 계획도와 실제 건설 미리보기를 제공하는 로컬 시험 빌드. 실제 건설은 별도 버튼으로 요청하며 게임의 임시 건설 검사에서 오류가 있으면 확정할 수 없다. 공원·외부 시설·지하주차장 진입로는 현재 계획 구역만 표시한다. 실제 입주·차량 주차·전기·상하수도 공급·저장 재로드 검증은 진행 중이다.

## 0.1.11 실제 건설 시험

- 배치 조건에서 주 도로·주차장 통로·보도를 고른다. 게임 프리팹의 실제 전체 폭으로 배치를 다시 계산하고 선택을 저장한다.
- 실제 건설 미리보기는 도로·보도·선택 건물·기본 주차 데칼을 임시 생성한다. 미리보기 건설 버튼으로 확정하며, 도구 취소와 도시 저장은 별도다.
- 검색 결과 밖의 선택은 선택한 에셋만 보기로 확인하고 모두 해제할 수 있다.
- 건물의 도로 연결, 전기·물·하수 연결과 실제 수요/공급량을 별도로 검사한다. 연결 표시만으로 기능 정상이라고 판정하지 않는다.
- 검증 현황은 docs/native-construction-review.md를 따른다. 현재 완성된 실건설 모드로 배포하지 않는다.

## 0.1.10 게임 UI와 경계 편집

- 닫힌 구역은 미리보기와 입구 모드에서도 꼭짓점·변을 드래그하여 수정한다. 입구 모드의 짧은 클릭은 입구 지정, 드래그는 경계 이동이다. 입구는 원래 변 위의 비율을 유지해 따라간다. 자기 교차하거나 수동 구역을 잘라내는 이동은 취소한다.
- 메인 도로 모서리는 배치 조건 탭 버튼 또는 옵션에서 0 곡선 우선·불가능하면 직각(기본), 1 곡선만, 2 직각으로 바꾼다. 설정은 재실행 후 유지된다. 도로 전체 폭·제외 범위 검사는 모든 모드에서 유지한다.
- 게임 기본 버튼 스타일 때문에 검어진 글자와 밝아진 비활성 버튼 배경을 명시적 색상으로 보정했다. 건물을 배치하지 못한 경우 별도 안내를 표시한다.

## 0.1.9 UI와 검토

- 헤더를 잡아 이동하고 가로 배치, 도구 이름 숨기기, 패널 접기를 선택한다. 위치와 표시 상태를 기억하며 화면 밖으로 나가지 않게 보정한다.
- 에셋, 배치 조건, 면적 현황, 저장 목록을 탭으로 분리했다. 에셋 이름은 두 줄, 전체 이름은 툴팁으로 확인한다. 보정할 에셋 이름을 누르면 숫자 입력이 펼쳐진다.
- 버튼 기호와 단위는 SVG로 표시한다. 설명은 정보 아이콘이나 해당 기능에 마우스를 올려 확인한다. 배치 수치 전체는 게임 옵션의 Apartment Plan에서 조절한다.
- 용적률 상한 초과, 큰 녹지 여백의 입구 연결, 작은 입구 어긋남 연결, 작은 에셋 교체의 전면 유지 문제를 보완했다.
- 배치 검사와 브라우저 UI 검사를 통과했다. 게임 내부 UI와 실제 차량 주행을 검증한 결과는 아니다.

## 사용

1. 도시를 불러온 뒤 오른쪽 위 Apartment Plan 아이콘 클릭.
2. 지면을 클릭해 다각형 꼭짓점을 지정. 첫 점 근처 클릭, Enter 또는 **구역 완료**로 닫기. 우클릭은 마지막 점 취소.
3. 경계선을 클릭해 첫 입구 지정. **입구 추가**를 눌러 최대 16개까지 더 지정할 수 있다. 입구 모드에서 우클릭하면 최근 입구가 제거된다. 기본 주 도로는 Small Road이며 선택 프리팹 전체 폭을 배치에 적용한다. 기본 입구 길이는 15m이며 도로 폭에 필요한 길이를 확보한다. Shift+R / Shift+T 또는 배치 조건 탭의 증감 버튼으로 전체 입구 길이를 2m씩 변경한다. 도로의 전체 프리팹 폭과 차도 폭은 다르다.
4. 아파트 에셋을 여러 개 선택. 목록은 기본적으로 세대수 2 이상 건물만 표시하며, 사용자 에셋이 없으면 **비주거 에셋 포함**를 선택. 부지 크기는 게임 BuildingData의 셀 크기 × 8m, 높이는 ObjectGeometryData에서 읽는다.
5. 내부 도로, 지상 주차장, 주거동과 잔여 녹지가 함께 계산된다. **외부 시설 제외 범위**는 사용자가 지정한 다각형을 배치 가능 영역에서 빼는 기능이다. 기본값은 없음이며 학교·시설·놀이터를 자동 배정하지 않는다. 제외 영역에는 건물·주차·도로·녹지 도형을 채우지 않는다. 제외 범위끼리는 겹칠 수 있다. 놀이터와 공원은 별도 수동 구역으로 추가할 수 있다. 각 다각형은 최소 100m²이며 단지 안에 있어야 한다. 입구와 충돌하거나 도로 연결이 불가능하면 거부한다. Enter·구역 완료·첫 점 클릭으로 닫고 최근 구역 취소로 되돌린다.
   **개별 동 교체** → 계획도 동 클릭 → 목록 에셋 선택으로 그 동만 교체한다. 현재 자리와 같거나 작은 부지 에셋만 허용하며 빈 부분은 포장 공간으로 남는다. 전체 다시 계산은 개별 교체를 초기화한다. 지하주차장 진입로 토글을 켜고 도로 및 다른 진입로와 겹치지 않는 지면을 클릭하면 수동 계획 구역을 추가하고 주변 계획을 다시 계산한다. 우클릭으로 최근 진입로를 취소할 수 있다.
6. **계획도 저장** 후 메뉴를 닫아도 불투명도 0.6으로 유지. 편집 중은 0.8. 게임을 다시 시작해도 유지하려면 **도시 세이브도 저장**해야 한다.

저장한 계획도는 이 도시의 메타데이터에 포함된다. 다른 도시 로딩 시 편집 중 계획과 메모리 캐시는 비운다. 저장 목록의 삭제 버튼을 두 번 눌러 해당 계획도만 삭제한다. 편집 중 변경은 저장 전까지 도시 세이브에 포함되지 않는다. 저장한 도형의 재편집은 현재 지원하지 않는다.

## 계산과 옵션

- 추정 용적률 = 합계(건축면적 × 추정 층수) / 지정 구역 면적 × 100. 기본 층고 3m. 건축면적 기본값은 부지의 70%; 에셋별 보정에서 0을 입력하면 이 비율을 사용한다. 실제 연면적이 없는 에셋의 추정치이며 법규 검토 기능이 아니다.
- 설정값은 게임 옵션 → Apartment Plan에서 변경하고 **다시 계산**으로 적용한다. 게임 표준 설정 저장소에 수치·스위치·색상·입력 설정을 저장한다. 패널 ± 입구 길이, 전면 주차 토글, 선택 에셋 ID와 에셋별 높이·건축면적·세대수 보정도 저장·복원한다. 검색어·목록 필터·패널 위치·표시 방식은 UI 저장소에 보존한다. 보정값과 선택 에셋 기록은 수치 기본값 복원으로 지우지 않는다.
- 건물·주차줄·통로를 하나의 후보로 함께 배치한다. ㄷ·ㅁ·평행 두 동·ㅡ·ㅣ 단독 동을 부지에 맞춰 시도하며 전역 최적 배치를 보장하지는 않는다. 끝선 어긋남 기본 2m. 에셋의 실제 부지 치수는 유지한다.
- **모든 동의 인근 주차 확보** 기본 켬. 부지 경계에서 40m 이내에 최소 4면인 주차줄이 있으면 건물 앞·옆·뒤 어디든 공유할 수 있다. 주차줄의 방향도 건물 방향과 독립적이다. 기존 설정 ID `RequireFrontParking`, `FrontParkingDistance`, `MinFrontParkingSpaces`는 보존한다. 전면 투영 겹침 비율은 더 이상 사용하지 않으며 기존 값만 숨겨 보존한다.
- 주차줄 방향은 **0 양쪽 검토 / 1 주 동과 평행 / 2 직교 우선**으로 조절한다. 직교 마당의 폭·깊이가 부족하면 평행 대안을 검토한다. 건물 에셋 자체를 회전시키는 설정과 별개다.
- **건물 전면도로 필수 (계획도)** 기본 켬. 끄면 기존 주차 마당을 공유하는 잔여 동을 전면도로 없이 추가할 수 있다. 게임의 건물 프리팹·도로 접근·서비스 시뮬레이션은 변경하지 않는다. 주차장의 차량 연결 조건은 이 옵션과 무관하게 유지한다.
- 각 주차줄의 실제 칸 수·깊이·방향, 주차칸이 열리는 쪽의 통로 전 폭, 양끝 진입 여유 기본 3m, 입구까지 최소 3m 연속 차량 통로를 검사한다. 모든 칸의 진입점과 입구로 이어지는 경로를 계산한다. 실패가 있으면 계획도 저장을 막고 안내한다. 이 검사는 양방향 평면 통로를 가정하며 실제 자동차 회전 궤적·지형 경사·네이티브 LaneConnection 생성을 검증하는 기능은 아니다.
- 메인 도로는 기존 회색, 주차 마당과 연결 통로의 invisible road는 기본 연회색 `#D9DCDF`로 표시한다. 색은 설정에서 변경 가능하다. 새 계획은 저장 버전2/표시 종류10을 사용하며 기존 버전1도 읽는다. 기존 도로 도형은 종류를 추측해 다시 칠하지 않는다.
- **경계 녹지 여백 4m**, 평행 긴 면 간격 **24m**, 단부·직교 간격 **8m**, 메인 도로 주차 이격 **6m**가 기본이다. 경계 여백은 건물·주차에 적용하며 입구와 보행로는 통과할 수 있다. 높이별 일조권·법규 판정이 아니다.
- 주차칸 기본 2.5×5m. 주차 통로 6m + 양옆 포장 여유 각 1m. 넓은 마당 허용·통로 수 상한·녹지섬 폭·세대당 주차 수요·지상 주차 분담률을 조절한다. 필요하면 더 작은 마당 후보를 사용한다. 목표량을 못 채우면 부족량으로 표시하며 지하 주차 대수를 임의로 더하지 않는다.
- 묶음 유형 허용, ㅁ자 최대 수 2개, 잔여 단독 동 허용, 가로·세로 혼합, 세로 선호도 38%, 끝선 정렬, 접속도로 최대 40m, 탐색 간격 2m, 최대 100동, 보행로 생성과 테두리 보행로 간격 80m도 변경할 수 있다. 세로 선호도는 강제 비율이 아니다. 기하·저장 형식의 내부 안전 한도는 설정 대상이 아니다.
- 주차·공원 비율은 목표와 부족량 표시에도 사용한다. 인근 주차 필수 조건은 주차 목표 0%보다 우선한다. 자동 시설 비율의 기존 설정 ID는 읽기 호환을 위해 숨겨 보존하며 새 배치에 사용하지 않는다.
- 기본적으로 용적률은 배치 결과의 참고 수치다. **목표 용적률에서 건물 배치 중단**을 켠 경우에만 동 수를 제한한다. 경계 밖 배치, 구역 겹침, 입구에 연결되지 않는 블록은 확정하지 않는다.
- 부지 바깥으로 나가지 않는 제한된 격자를 계산에만 쓰고 같은 종류의 칸을 큰 직사각형으로 병합한다. 사선 경계는 작은 계단 형태로 근사한다. 포장 마당·보행공간은 녹지와 별도 색상으로 표시한다. 주차 구획선은 옵션에서 켜거나 끄고 다시 계산한다.
- 수치·색상·불투명도·입력 설정은 게임 옵션 → Apartment Plan. 변경 후 편집 계획은 **다시 계산**. 기존 저장 계획도는 생성 당시 도형을 보존하므로 새 알고리즘이 자동 적용되지 않는다. 실제 지형 경사·일조권·차량 주행 시뮬레이션을 판정하지 않는다.
- 부지 최대 1km², 변방향 범위 최대 2,048m, 꼭짓점 최대 128개. 계획당 최대 1,600구역, 저장 최대 32개 및 도형 총 12,000개. 배치 계산은 수정 때만 수행하며 단색 지형 투영 오버레이와 거리 제한을 사용한다.
- 메뉴는 RSIK 스타일의 상단 버튼, 어두운 패널, 아이콘, 가로/세로·아이콘 전용 전환과 제목줄 드래그를 제공한다.

## 개발·설치

`build.ps1`: 설치된 공식 CS2 Mod.props/Mod.targets, 후처리 도구와 로컬 CopyIt의 UI 개발 의존성 사용. `install-current.ps1`: 게임 종료 확인 후 `%USERPROFILE%/AppData/LocalLow/Colossal Order/Cities Skylines II/Mods/ApartmentPlan`에 로컬 설치. 기존 파일은 프로젝트 docs에 백업. 공개 배포 없음.

확인 범위: 공식 SDK 빌드/후처리, TypeScript/UI 빌드, 대표 다각형 배치·용적률·직렬화 필드 왕복 검사. 실제 게임에서 메뉴·입력·지형 투영·불투명도·도시 저장/재로드·성능은 아직 확인하지 않았다. 제거 후 게임 저장 호환성도 미검증이다.



## 0.1.1 동작 로그

모드 로딩 전부터 상세 로깅이 항상 활성화된다. `%USERPROFILE%/AppData/LocalLow/Colossal Order/Cities Skylines II/Logs/ApartmentPlan/`에 UTC 시각을 포함한 세션별 로그를 기록하며 8MiB마다 새 파일로 분할한다. 기존 로그는 지우지 않는다.

초기화/번역, 시스템·바인딩 등록, UI 장착·렌더 오류, 메뉴 클릭·명령 전달·처리·거부, 검색/페이지/레이아웃/창 이동, 입력 포커스·레이캐스트, 구역 점·입구·진입로, 에셋 선택/보정, 설정 변경, 계산 결과·소요시간, 저장·삭제·복원, 도시 직렬화 단계와 오버레이 상태를 기록한다. UI 로그는 게임의 UI 콘솔에도 남겨 게임 쪽 초기화 실패 시 전달 이전을 추적한다. 검색어 자체 대신 길이를 기록한다.

매 프레임 레이캐스트·렌더 상태는 변경 시 또는 같은 상태가 5초 지속될 때 요약하고 생략 횟수를 기록한다. 개별 사용자 명령은 생략하지 않는다. 도시 직렬화 종료 로그는 디스크 쓰기 성공의 증거와 구분한다.

0.1.0에서 게임이 DLL을 메모리로 로딩할 때 Assembly.Location이 비어 번역 경로 계산에 실패했던 문제를 수정했다. 기본 한영 번역은 동일 JSON 원본을 DLL에 포함해 읽는다.


## 0.1.2 구역 그리기와 에셋 타일

- 첫 꼭짓점부터 도로 경계·건물 부지·기존 부지·구역 격자에 스냅. 기본 반경 8m. 각 종류와 직각/연장선은 패널에서 개별 전환하며 옵션에 저장한다.
- 도로에 맞춘 첫 점의 방향을 이후 직각/평행 기준으로 사용한다. 가이드 교차점에서는 두 조건을 동시에 만족하는 점을 선택한다. 곡선 도로는 구간별 16개 선분으로 근사한다.
- 원형 꼭짓점/커서, 활성 경계 강조, 40m 양방향 가이드와 3m/2m 점선, 마지막 점→커서와 커서→시작점 미리보기를 표시한다. 길이·각도는 패널에 표시한다.
- 3점 이상일 때 시작점의 12m 안에 접근하면 녹색 마감 링을 표시하고 정확한 시작점으로 스냅한다. 교차하는 선이나 유효하지 않은 닫힌 구역은 확정하지 않는다.
- 그리는 중 기존 꼭짓점을 드래그할 수 있다. 닫은 후 **구역 편집**에서 꼭짓점 또는 변을 드래그하고 마우스를 놓아 확정. 우클릭/도구 이탈은 드래그 취소. 편집 상태에서 우클릭하면 다시 열린 그리기 상태로 돌아간다. 저장된 계획도 재편집은 기존과 같이 미지원.
- 주변 지형 요소는 게임 공간 검색 트리로 조회하고 최대 0.35초 캐시(커서 12m 이동 시 갱신)를 사용한다. 실제 시설 생성 없음.
- 에셋 목록은 한 페이지 4×4, 16개 타일. 이름·높이·세대수는 툴팁에서 확인. 숫자와 단위는 한 문자열로 표시하고, '모든 건물 표시'는 커스텀 선택 버튼을 사용한다.

PLT와 구역 그리기 흐름/가이드 표현을 맞췄지만 자체 구현이며 모든 PLT 편집 기능을 복제한 것은 아니다. 경계 곡선 근사 및 실제 게임 조작감은 게임에서 추가 확인이 필요하다.

## 0.1.4 판상형 주차 마당 (이전 알고리즘)

- 장단변 비율 2 이상, 긴 변 32m 이상인 부지를 판상형으로 **추정**한다. 실제 메시 형상 분류가 아니며 선택 에셋의 크기는 그대로 유지한다.
- 두 동 묶음은 기본 2개 통로/4개 주차 열로 넓힌다. 세대수 × 세대당 목표 면수 × 지상 배정 비율(기본 40%)을 구획 폭으로 계산한 수용량과 비교하여 최대 3개 통로까지 확장한다. 한 동짜리 경계 묶음은 1개 통로부터 시작한다. 세대수가 없으면 두 동 묶음의 기본 2개 통로를 사용한다.
- 기본 3m 녹지섬으로 주차 열을 나누고 각 통로를 블록 끝 도로에 연결한다. 통로·녹지 면적을 주차 면수로 계산하지 않는다. 미충족 주차 수요는 계속 표시하며 지하 수용 대수를 추정해 더하지 않는다.
- 옵션: 판상형 넓은 주차 마당, 지상 수요 배정 비율, 통로 수 상한, 녹지섬 폭. 공통 행·열 정렬을 유지하기 위해 정렬 블록의 마당 깊이는 선택 에셋 중 필요한 값에 맞춘다. 넓은 마당 때문에 배치 동 수는 줄 수 있다.

## 0.1.5 외곽 잔여 공간 활용 (이전 알고리즘)

기존 주거동과 정렬선을 고정한 뒤, 외곽에 기존 앞선·측면선을 연장한 단독 동 배치를 시도한다. 큰 주차 마당을 새로 요구하지 않고 기존 단지 주차장을 공유한다. 건물이 들어가지 않는 좁은 공간은 15~40m 길이의 주차 묶음을 같은 직교 방향으로 넣는다. 연결도로는 기존 도로까지 최대 32m 이내에서 전 폭이 들어가야 하며, 경계·건물·수동 진입로·시설과 겹치면 추가하지 않는다. 옵션 **외곽 잔여 공간에 건물 · 주차장 추가**로 전환한다. 기존 저장본은 바뀌지 않으며 편집 중 계획은 다시 계산한다.

## 0.1.6 복수 입구 · 수동 구역 · 단지 기준축

- 경계의 직교 방향군을 길이로 평가해 공통축을 정한다. 짧은 사선 변에 입구가 있다고 단지 전체를 그 변에 맞춰 기울이지 않는다. 단지 자체가 전체적으로 회전되어 있으면 그 회전은 유지한다. 사선 입구는 짧은 경계 접속부를 두고 내부 직교 도로로 연결한다.
- 입구를 잇는 주 도로를 건물보다 먼저 확보한다. 어긋난 두 입구는 접선 방향을 유지하는 곡선으로 잇는다. 직각 코너는 목표 반경 16m의 원호로 바꾸며 공간이 부족하면 도로 폭 1.5배(기본 12m)까지 줄인다. 이보다 작은 코너만 가능한 경우 연결을 거부한다. 단일 입구는 내부로 주 도로를 연장한다. 전 폭 장애물 검사를 하고, 경로 길이와 회전 비용을 함께 최소화한다. 통로가 도로 폭보다 좁으면 추가 입구를 거부한다. 도로 중앙 점선은 왕복 2차로 계획 표현이며 실제 차로 엔티티가 아니다.
- ㄷ자·반전·회전 묶음과 잔여 공간의 독립 동을 사용한다. 모든 동의 실제 부지 크기를 유지한다. 윤곽은 부지 직사각형이며 메시의 돌출부를 그대로 그린 실루엣은 아니다.
- 건물·시설에서 입구 측 보행망 및 경계 방향으로 직교 보도를 연결한다. 주차칸과 건물은 피하고 차도 위에서는 직진 횡단만 허용한다. 필수 시설 연결을 찾지 못하면 패널에 표시하며, 막힌 외곽 보도 후보는 생략한다. 지형 경사·차량 회전 궤적을 검증한 도로 설계는 아니다.
- 수동 구역과 나머지 녹지는 1~6m 계산 격자로 근사된다(현재 크기 상한에서는 최대 6m). 테두리에 작은 계단이나 보수적 여유가 생길 수 있다. 완성 계획은 기존 버전 1 도형 저장 형식을 그대로 사용한다.
- 예시 축척 추정: 첨부 이미지 주차칸 폭을 약 2.5m로 놓으면 폭 약 150~170m, 길이 약 310~340m. `docs/offset-reference.png`는 160×325m 사선 부지, 옆으로 60m 어긋난 두 입구, 학교·공원 예약 구역에 예시 부지 치수 40×12m / 24×12m를 넣은 계산 결과이며 게임 캡처가 아니다. 현재 26동(가로 13·세로 13), 주차 338면이다. 같은 조건의 이전 마당 강제 방식은 13동·272면이었다. 렌더의 색상은 첨부 이미지 설명용으로 맞췄고 기존 게임 설정 색상을 변경하지 않는다.
- 이 모드는 실제 주차장·도로를 생성하지 않으므로 ParkingLane 안락함이나 주차료를 변경하지 않는다. Parking Lot Tool의 실제 주행·주차 기능까지 제공한다고 해석하면 안 된다.

등록 오류 수정: 기존 게임 로그에서 확인된 `Alley utility sections incomplete: None`은 지하 전기·수도 섹션을 탐색하지 않은 문제였습니다. 내장 `UndergroundNetSections`와 `OverheadNetSections`도 각각 유지하여 복제하도록 수정했습니다. 재시작 후 실제 등록 및 공급 확인은 아직 필요합니다.





## 로컬 계산 시간 진단

일반 `./build.ps1 -SkipLayoutTests` 빌드는 상세 계산 시간 로깅이 켜진 로컬 테스트용입니다. `-LocalDiagnostics`도 같은 동작입니다. 설치 후 게임에서 계획도를 계산하면 Logs/ApartmentPlan/*.log에 `layout.localTiming`으로 실행 ID, 단계별 시간(ms), 총시간 및 실패/취소를 기록합니다. 별도 DebugLogging 활성화는 필요 없습니다.

공개 패키지는 반드시 `./build.ps1 -SkipLayoutTests -PublicRelease`로 생성하고 DLL 메타데이터 `ApartmentPlan.LocalLayoutTiming=false`를 확인합니다. 로컬 ZIP이나 `LOCAL-DIAGNOSTICS-DO-NOT-PUBLISH.txt`가 있는 패키지는 게시하지 않습니다. 공개 게시 성공과 ALL VERSIONS 등록 확인 후에는 일반 빌드로 로컬 계측판을 다시 만들고 게임 종료 상태에서 설치합니다. 게임 실행 중이면 설치 대기로 남깁니다. 공개 게시 승인은 별도로 필요합니다.
